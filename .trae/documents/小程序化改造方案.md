# 小程序化改造方案

## 1. 目标与范围

将现有 Flutter 记账 App 迁移为微信小程序，复用现有 FastAPI 后端，Flutter 客户端保持可用、不删除。

交付方式：按第 7 节分批实施。**首批只搭工程骨架并跑通登录，验收后再逐批迁移页面**，不一次性铺开全部功能。

首版范围（不含 AI）：

- 微信一键登录 + 账号密码登录兜底
- 首页：月度收支汇总、按日分组账单、切月
- 记账：新增/编辑收支
- 账单：周/月/年浏览、关键词与分类/标签/类型筛选、编辑、删除
- 物品：列表、汇总、筛选、新增/编辑/出售/删除
- 报告：周/月/年统计、收支环图、分类饼图、分类柱状图、趋势折线图、预算设置
- 我的：资料修改、分类管理、标签管理、账单导入、账单导出（XLSX）、多账号管理、隐私政策、注销账号、退出登录
- 隐藏 AI 对话页面，后端 `/api/chat/*` 保留不动

不做：

- web-view 套壳
- 支付宝/抖音小程序（uni-app 结构上可扩展，但首版只验证微信端）
- 深色模式（首版固定浅色，保留 CSS 变量，后续再接 `darkmode` + `theme.json`）
- 整库 `.db` 备份下载（小程序无法打开该格式，首版只保留 XLSX 导出）

## 2. 现状分析

### 2.1 客户端

- 5 个主 Tab，顺序为：记账、账单、物品、报告、我的（[main.dart](../../lib/main.dart#L76-L92)）。
- 13 个页面，约 1 万行 Dart：`auth`、`home`、`add_transaction`、`bills`、`items`、`item_edit`、`report`、`settings`、`category_manage`、`tag_manage`、`user_manage`、`bill_import`、`ai_chat`。
- 登录态与本地配置存于 `shared_preferences`：
  - `auth_token`、`auth_user`（[auth_config.dart](../../lib/config/auth_config.dart#L15-L57)）
  - `api_base_url`（[api_config.dart](../../lib/config/api_config.dart#L4-L48)）
  - `theme_mode`（[theme_config.dart](../../lib/config/theme_config.dart#L4-L39)）
- 请求统一走 `ApiClient`，自动附加 `Authorization: Bearer <token>`，401 时清登录态（[api_client.dart](../../lib/api/api_client.dart#L27-L37)、[api_client.dart](../../lib/api/api_client.dart#L141-L154)）。

- 主题色取自 `AppColors.light`（[app_colors.dart](../../lib/constants/app_colors.dart#L63-L81)）：背景 `#F4F5FB`、主色 `#6366F1`、收入 `#16A34A`、支出 `#DC2626`、次级文字 `#5A5A72`、分割线 `#E4E6F0`。

### 2.2 后端接口（均已存在）

| 模块 | 接口 |
|---|---|
| 认证 | `POST /api/auth/register`、`/login`、`/logout`、`GET/PUT /api/auth/me`、`DELETE /api/auth/me`、`GET /api/auth/status` |
| 用户 | `GET/POST /api/users`、`DELETE /api/users/{id}` |
| 分类/标签 | `GET/POST/PUT/DELETE /api/categories`、`/api/tags` |

| 报表 | `GET /api/reports/categories`、`/api/reports/trend`、`PUT /api/budgets` |
| 物品 | `GET/POST /api/items`、`GET /api/items/summary`、`PUT/DELETE /api/items/{id}` |
| 导入 | `POST /api/imports/preview`（multipart）、`POST /api/imports/commit` |
| 导出 | `GET /api/exports/transactions.csv`、`/api/exports/transactions.xlsx`、`/api/exports/backup.db` |
| AI | `/api/chat/*`，首版前端不接 |

账单查询参数：`year`、`month`、`start`、`end`、`q`、`category_id`、`type`、`tag_id`。

### 2.3 已具备的后端能力

- 注销当前账号：`DELETE /api/auth/me`，会清理全部关联数据。
- XLSX 导出：`GET /api/exports/transactions.xlsx`。
- 注册控制：`REGISTER_ENABLED`、`REGISTER_INVITE_CODE`，首个账号始终可注册。
- `/api/auth/status` 返回 `has_users`、`registration_open`、`invite_code_required`。

### 2.4 缺口

- 没有微信登录接口，`users` 表没有 `wx_openid`。
- 没有 `miniapp/` 工程。
- 前端能力需要替换：`shared_preferences` → `uni.*Storage`；`http` → `uni.request`；`file_picker` → `wx.chooseMessageFile`；本地保存文件 → `downloadFile + openDocument`；`fl_chart` → uCharts。

## 4. 后端改造：微信登录

### 4.1 新增 `server/wechat.py`

职责：只做微信 `code2session` 调用与配置判断，不碰数据库。

```python
def is_configured() -> bool          # WX_APPID 和 WX_SECRET 都非空
def exchange_code(code: str) -> str  # 返回 openid，失败抛 HTTPException
```

- 读取环境变量 `WX_APPID`、`WX_SECRET`。
- 调用 `https://api.weixin.qq.com/sns/jscode2session`，参数 `appid`、`secret`、`js_code`、`grant_type=authorization_code`，`httpx.get(timeout=10)`。
- `errcode` 非 0 时：`40029/40163` → 401「登录凭证已失效」，`45011` → 429「操作过于频繁」，其他 → 502「微信登录失败」。
- 只返回 `openid`；`session_key` 不返回、不落库、不打日志。

### 4.2 数据库迁移

`server/sql/schema.sql` 的 `users` 表增加 `wx_openid TEXT`。

`server/database.py` 新增 `_migrate_wechat(conn)` 并加入 `init_db()` 的迁移链（在 `_migrate_users_is_admin` 之后）：

- 旧库补列：`ALTER TABLE users ADD COLUMN wx_openid TEXT`
- 唯一索引：`CREATE UNIQUE INDEX IF NOT EXISTS idx_users_wx_openid ON users (wx_openid) WHERE wx_openid IS NOT NULL`（SQLite 允许多个 NULL）

### 4.3 `server/auth.py`

新增 `login_with_wechat(code: str) -> dict`：

1. `wechat.is_configured()` 为假 → 503「微信登录未配置」。
2. `openid = wechat.exchange_code(code)`。
3. 按 `wx_openid = openid` 查用户：
   - 命中：直接开 session。
   - 未命中：在同一事务内创建用户
     - `username = "wx_" + openid[:16]`，冲突时追加 `openid[-6:]`
     - `password_hash = hash_password(secrets.token_urlsafe(24))`（用户不感知）
     - `display_name = "微信用户"`
     - 复用 `_insert_user` 以继承首用户 admin 判定与默认分类/标签初始化
     - `UPDATE users SET wx_openid = ? WHERE id = ?`
4. `_open_session` 后返回 `{"token": token, "user": _user_out(row)}`，与账号密码登录返回结构一致。

`auth_status()` 增加 `"wechat_login_configured": wechat.is_configured()`。

### 4.4 `server/main.py`

- 新增请求模型 `WechatLoginIn(BaseModel): code: str`。
- 新增 `POST /api/auth/wx-login`，调用 `login_with_wechat`，不需要登录。
- 不改动现有账号密码接口。

### 4.5 配置与文档

- `server/.env.example` 增加 `WX_APPID=`、`WX_SECRET=`。
- `docs/backend-deploy.md` 环境变量表补两行，并注明 AppSecret 只放服务端。

### 4.6 测试

在 `server/test_ledger.py` 新增 `WechatLoginTest`：

- 未配置时返回 503。
- mock `wechat.httpx.get` 返回 openid：
  - 首次登录创建用户并生成默认分类
  - 第二次登录复用同一 `user.id`
  - 返回的 token 可被 `require_user` 识别
- mock 返回 `errcode=40029` 时返回 401。

### 5.1 工程初始化

用官方模板创建后锁定依赖版本：

```bash
npx degit dcloudio/uni-preset-vue#vite-ts miniapp
cd miniapp && npm install
npm i @qiun/ucharts
```

`package.json` 脚本：

```json
{
  "dev:mp-weixin": "uni -p mp-weixin",
  "build:mp-weixin": "uni build -p mp-weixin",
  "type-check": "vue-tsc --noEmit"
}
```

`manifest.json` 关键项：

- `appid`：先填 `wx0000000000000000` 占位，接入真实 AppID 时替换
- `mp-weixin.setting`：`urlCheck: false`（仅开发）、`es6: true`、`minified: true`
- `mp-weixin.usingComponents: true`
- 不开启 `darkmode`

### 5.2 `pages.json`

- 首屏 `pages/login/index`；已登录时 `onLoad` 直接 `uni.switchTab` 到首页
- Tab 页：`pages/home/index`（记账）、`pages/bills/index`（账单）、`pages/items/index`（物品）、`pages/report/index`（报告）、`pages/settings/index`（我的）
- tabBar 纯文字，选中色 `#4338CA`，未选中 `#8B8BA3`
- 首页、账单、物品、报告开启 `enablePullDownRefresh`
- 全局导航栏：背景 `#F4F5FB`、文字 `#1A1A2E`

### 5.3 基础设施

`src/api/http.ts`：

- `request<T>({url, method, data, query})`：拼接 `API_BASE_URL`，注入 Bearer，超时 30s
- 统一错误：`{detail}` 优先；401 清 session 并 `uni.reLaunch({url:'/pages/login/index'})`
- `upload<T>(path, filePath, formData)`：`uni.uploadFile`，手动带 Authorization
- `download(path, filename)`：`uni.downloadFile`，返回临时路径

`src/stores/session.ts`：

- `state: { token, user }`，`restore()` / `save()` / `clear()`
- `loginWithWechat()`：`uni.login({provider:'weixin'})` → `POST /api/auth/wx-login`
- `loginWithPassword()` / `register()`（带 `invite_code`）
- `logout()`：调 `/api/auth/logout`，无论成功都清本地
- `deleteAccount()`：`DELETE /api/auth/me` → 清本地 → 回登录页

`src/utils/money.ts`：`centsFromYuan(v) = Math.round(Number(v) * 100)`、`formatYuan(cents)`，与 Dart 端一致。

`src/styles/theme.scss`：把 `AppColors.light` 的 17 个颜色映射为 `--color-*` 变量，页面只引用变量，方便后续加深色模式。

### 6.1 图表封装

`components/chart-canvas.vue`：

- 使用 `<canvas type="2d" id="...">`，通过 `uni.createSelectorQuery` 获取节点
- `uCharts` 实例化，`pixelRatio = uni.getSystemInfoSync().pixelRatio`
- 监听 `options` 变化重绘；页面 `onUnload` 销毁
- 支持四种类型：`ring`（收支结构）、`pie`（支出分类）、`column`（分类对比）、`line`（趋势）

### 6.2 导入导出

- 导入只支持从微信聊天记录/收藏选择文件；需在页面明确提示，避免用户找不到「手机文件」
- `uni.uploadFile` 的 `name` 固定为 `file`，与后端 `UploadFile` 参数一致
- 导出：`GET /api/exports/transactions.xlsx` → `downloadFile` → `openDocument({fileType:'xlsx'})`
- `.db` 备份入口在小程序中隐藏

### 6.3 账号注销与隐私

- 设置页「注销账号」：红色危险项 → 二次确认弹窗（输入「注销」二字）→ 调 `DELETE /api/auth/me` → 清本地 → 登录页
- 登录页底部展示《用户协议》《隐私政策》链接，未勾选不可登录
- 小程序后台的《用户隐私保护指引》按部署清单配置，代码侧不重复实现平台弹窗

### 6.4 刷新与联动

- 所有 Tab 页在 `onShow` 首次加载并刷新
- 新增/编辑账单、物品后 `uni.navigateBack()`，来源页 `onShow` 自动刷新
- 报告页点分类：写 `bills-filter.set({period, start, end, categoryId, type})` → `uni.switchTab('/pages/bills/index')`
- 设置页切换账号/退出后 `uni.reLaunch('/pages/login/index')`

## 7. 实施顺序（分批交付）

原则：每批独立验收，**验收通过并确认后再进入下一批**。前端页面按优先级分批迁移，未轮到的 Tab 显示占位页，不提前实现。

### 批次 1（立即执行）：骨架 + 登录跑通

目标：跑通「打开小程序 → 登录 → 进入 5 个 Tab」的最小链路，不实现业务页面。

执行顺序：先完成后端接口与测试，再初始化小程序工程接入登录；避免前端等接口。

后端：

- 新增 `server/wechat.py`
- `users` 表迁移 `wx_openid` 并建唯一索引
- `auth.login_with_wechat`、`POST /api/auth/wx-login`
- `/api/auth/status` 增加 `wechat_login_configured`
- `.env.example`、部署文档、单测

小程序：

- 用官方 vite-ts 模板初始化 `miniapp/`
- `pages.json`、`manifest.json`（AppID 占位）、`theme.scss`
- `api/http.ts`、`stores/session.ts`、`utils/money.ts`、`config/index.ts`
- `pages/login/index.vue`：微信一键登录为主，未配置或失败时展示账号密码表单；读取 `auth/status` 判断注册开关与邀请码
- 5 个 Tab 占位页：首页、账单、物品、报告、我的
- `pages/privacy/index.vue` 占位页
- `.env.development` / `.env.production`

验收：

- `python3 -m unittest test_ledger -v` 全绿
- 后端未配置微信时 `wx-login` 返回 503，配置 + mock 时可创建并复用用户
- 开发者工具「不校验合法域名」下完成登录，进入首页
- 杀掉小程序重开，登录态保留
- token 失效时自动回登录页
- 5 个 Tab 可切换，未实现页面显示「建设中」

## 9. 假设与决策

1. **AppID/AppSecret 可能暂缺**：微信登录接口通过环境变量开关；未配置时小程序自动展示账号密码登录，不阻塞开发。真实 `wx.login` 联调需要真实 AppID。
2. **Flutter 客户端保留**：后端接口保持兼容，不改现有字段；小程序新增字段均为可选。
3. **首版不接 AI**：页面不迁移，后端聊天接口与数据表保留，后续企业主体完成备案后再开。
4. **首版浅色主题**：CSS 变量已准备好；深色模式需要 `manifest.json` 开启 `darkmode` 并补 `theme.json`，列入后续迭代。
5. **整库备份不迁移**：小程序无法打开 `.db`，只保留 XLSX。
6. **服务端仍是 SQLite 单进程**：本次不引入 MySQL，遵循现有部署约束。
7. **TabBar 先纯文字**：避免额外图标资源与审核问题；后续可补图标。
8. **域名、HTTPS、备案**：按现有上线清单执行，不在本次代码改造范围内。
9. **分批交付**：每批完成后暂停确认；首批只交付骨架与登录，业务页面在后续批次实现。
10. **登录兜底**：微信登录是主路径，账号密码是开发期与未配置 AppID 时的兜底路径，两者共用同一套 token。

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| `@qiun/ucharts` 在 mp-weixin 下渲染异常 | 回退 `qiun-data-charts` uni_modules；再不行用 canvas 2d 手写四种图 |
| 微信登录需要真实 AppID，测试号可能不支持 | 开发期用账号密码兜底；联调阶段再换真实 AppID |
| `chooseMessageFile` 只能选聊天文件，用户找不到入口 | 页面文案明确提示「从微信聊天/收藏选择」，并提供格式说明 |
| 小程序主包超 2MB | 不引入 UI 库；图表按需引入；图片压缩 |
| uni-app CLI 版本漂移导致构建失败 | 使用官方模板并锁定 `package-lock.json`；不逐个手写版本号 |
| 报告页与账单页筛选联动失效 | 用独立 `bills-filter` store，`switchTab` 后在 `onShow` 消费并清空 |
| 登录态过期后停留在空白页 | `http.ts` 统一 401 拦截，`reLaunch` 登录页并提示 |
